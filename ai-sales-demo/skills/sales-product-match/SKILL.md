# Подбор предложения по базе

## Материалы
Нужны бриф клиента и утверждённый каталог: идентификатор продукта, состав, цена, валюта, период оплаты, ограничения, дата версии. Если важного поля нет, запроси его у ответственного, а не восстанавливай из памяти модели.

## Порядок работы
1. Сопоставь требования с параметрами каталога. Отдели обязательные требования от пожеланий.
2. Выбери не более трёх подходящих вариантов. Для каждого объясни, какое требование он закрывает и какое ограничение остаётся. Если ни один не подходит, скажи об этом.
3. Назови опубликованную цену и состав. Скидки, наличие, дополнительные платежи и сроки бери только из подтверждённых данных.
4. Расчёт выполняй детерминированным кодом приложения по идентификаторам и значениям каталога. Модель не должна быть источником итоговой суммы. Проверь валюту и единицы; не смешивай месячную и разовую цену.
5. Предложи уместный следующий шаг без вымышленной срочности. При конфликте версий приостанови спорную часть ответа и передай вопрос человеку.

## Результат
Вариант / почему подходит / состав / цена и условия / источник с версией / ограничения / следующий шаг. Внутренние ссылки на документы можно хранить в журнале проверки, не раскрывая закрытые данные клиенту.

## Проверка
Каждая коммерческая цифра выводится из каталога. Нет выдуманных услуг, гарантий и «последних мест». Неизвестное наличие не означает «в наличии».
