# ИИ-продажник — первая версия (демо-прототип)

Сделано по заданию из подарочного материала (Никита Бархатов, операционный директор Noya AI).
Продукт для демо выбран условно — услуги вашего проекта **IT-Service Online** (сайты под ключ),
чтобы прототип был не абстрактным, а похожим на реальную задачу. Поменять продукт — дело пяти минут
(см. «Как изменить продукт и цены» ниже).

## Что это и чего это НЕ делает

Это рабочий прототип тестового чата с правило-движком вместо настоящей языковой модели.
Он показывает поведение, описанное в задании: ведёт клиента по сценарию «вопрос → уточнение
потребности → подбор → согласие → заявка → передача человеку», не выдумывает цены, не даёт
самовольных скидок, останавливается по просьбе о человеке, не создаёт дублей заявки, не поддаётся
попыткам «обойти правила» через текст клиента.

Чего здесь нет (сознательно, как и требует задание для первой версии):
- настоящего вызова языковой модели (OpenAI/Anthropic/др.) — сейчас это детерминированные
  правила по ключевым словам; реальная версия вызывала бы модель с текстами навыков
  (`skills/*/SKILL.md`) как системными инструкциями;
- реальной отправки заявки менеджеру — это заглушка (`delivery_status: "demo"`);
- оплаты, CRM, мессенджеров, массовых рассылок и холодных сообщений — всё это вне границ
  первой версии по заданию.

## Файлы в пакете

```
index.html              — та же демка, что открывается по ссылке (можно открыть просто файлом в браузере)
engine.js               — вся логика: машина состояний, подбор по каталогу, навыки, заявка
catalog.json             — каталог услуг с ценами и версией прайса
tests.js                — 14 приёмочных сценариев из задания, прогоняются командой node tests.js
test-report.json         — результат последнего прогона тестов (14 из 14 пройдено)
skills/*/SKILL.md        — текстовые инструкции шести навыков из задания (копия приложения B)
```

## Как посмотреть демо

Самый простой способ — открыть ссылку на опубликованную демо-страницу (она прислана отдельно
в переписке). Там чат с подсказками-кнопками ("Нужен лендинг для кафе", "Сколько стоит?" и т.д.),
внутренняя панель с карточкой заявки и кнопка «Стоп», которая немедленно отключает автоответы.

Если нужно открыть локально: скачайте файл `index.html` и откройте его двойным щелчком —
браузер откроет его как обычную веб-страницу, никакой установки не требуется.

## Как прогнать тесты (для разработчика)

Нужен установленный Node.js (без дополнительных библиотек). В папке с файлами:

```
node tests.js
```

Выведет построчно каждый из 14 сценариев и итог. Последний прогон: **14 из 14 пройдено**.

Что проверено автоматически (этими тестами): выбор варианта по каталогу, ответ на цену без
требования телефона, честный отказ придумывать цену, обнаружение конфликта цен между двумя
версиями прайса, отказ от самовольной скидки, уважение отказа оставить контакт, передача человеку
и остановка продажи, отсутствие дублей заявки при повторной отправке, отсутствие лжи об успехе
при сбое отправки, устойчивость к попытке «отменить правила» текстом клиента, изоляция чужого
диалога, ограниченное число повторов при сбое модели, работа кнопки «стоп».

Что проверено только вручную/глазами (не входит в автотесты): как чат выглядит на телефоне и на
компьютере, индикатор «печатает…», реальный клик по кнопке в интерфейсе, вид внутренней панели.
Связь с настоящей моделью не подключена и не тестировалась — её в прототипе физически нет.

## Как изменить продукт и цены

Откройте `catalog.json` — там простой список: название, цена, срок, что входит, что не входит,
и `version` (дата/номер прайса). Поменяли цену — поменяли `version`, чтобы было видно, какой прайс
актуален. Тот же список (на сейчас — копия) встроен и в `index.html`, его тоже нужно поправить,
если меняете каталог для живой демки по ссылке.

## Что нужно для одного реального канала

1. **Настоящая модель.** Выбрать провайдера (OpenAI, Anthropic и т.п.) вместе с вами — цены и
   возможности не выдумываются, берутся из официальной документации на момент подключения. Ключ
   живёт только на сервере, в браузер не попадает.
2. **Реальный канал.** Сейчас это тестовый веб-чат. Для Telegram/сайта-виджета/WhatsApp нужен
   отдельный коннектор — это отдельная, более простая задача после того, как логика проверена здесь.
3. **Куда падает заявка.** Сейчас — заглушка. Нужно решить, куда реально передавать заявку
   (Telegram-уведомление вам, CRM, таблица) — по уже готовому контракту карточки заявки
   (`lead_id`, `contact`, `need`, `product_id`, `next_step`, `delivery_status`).
4. **Согласие на обработку контактов.** Перед работой с реальными клиентами — согласовать текст
   согласия, что и сколько хранится, как удалить данные по просьбе. В демо это не собирается.

## Ограничения, о которых стоит знать

- Распознавание намерений — по ключевым словам и шаблонам, а не по смыслу. Настоящая модель
  поймёт клиента гораздо лучше; это цена демо-режима без реального вызова модели.
- Каталог сейчас простой список в файле, без истории изменений и прав доступа — для первой
  версии этого достаточно, как и написано в задании.
- Это не juridически проверенный и не "законный по чек-листу" продукт — его таким и не называем;
  проверка соответствия конкретным требованиям (закон о персональных данных и т.п.) не входила
  в задачу первой версии и не была сделана.
